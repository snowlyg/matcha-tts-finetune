# 文本层书面边界：回归台

这里放的**不是**实现，是验证台。实现住在调用方仓库（OpenHarmony 那个 HAR 仓）的
`src/main/ets/tts/RtcTtsText.ets`：`normalizeTtsText` = 时刻/逐位编号/算符 → 字母分号 → 长句锚点逗号 → 数量短语后句号。

为什么这个仓要留一个跑别人源码的脚本：本仓的主线结论是"**不改模型，只改喂进去的书面边界**就能把
定向数字播报的错率从 24.2% 压到 3.6~4.8%"（取证见 `docs/icefall-finetune-flow.md`，端侧复核见
`docs/device-runtime-check.md`）。规则一旦落到另一个仓，两边的期望就会各改各的、慢慢漂移。
这个脚本把**真源码**和**对方的 Hypium 断言**一起读进来跑，漂移当场暴露。

```bash
RTC_SRC=/path/to/src/main/ets/tts/RtcTtsText.ets \
RTC_TEST=/path/to/test/RtcTtsText.test.ets \
  node scripts/textlayer/check_textlayer.mjs
```

不猜对方仓库在哪：两个环境变量都不给就直接退出。

## 三条规矩（每条都用一次真实事故换来的，别"顺手统一"）

| 场景 | 用的符号 | 为什么不能换 |
|---|---|---|
| 长句切分（≥14 字且原文无标点） | 半角 `,`，最多两刀 | 按字数硬切会把 `护士站/请` 切成破词，模型接着把音节读乱（"护士战""情紧快"）；分号在中文句里稳定性陪葬（8 次跑出 5 种结果） |
| 字母串逐个念 | `;` | 同一位置换顿号/逗号要多花 1.1~1.35 秒，且顿号那档八次跑出**七种**结果 |
| 数量短语后 | `。` | 边界加在数字**前面**没有降错收益（23.8%），床号反而恶化到 76%；小数点**不算**断句标点，否则带体温读数的句子整句放行 |

三种符号不能统一成一个，是因为它们各自是被实测挑出来的不同解，不是风格偏好。

## 已知代价（都是量的，不是猜的）

- 加 `。` 让这条播报**拆成两次独立推理**：音频 +0.29~0.43 秒，**合成耗时 +35%~53%（+0.98~1.19 秒）**。
  连播排队的压力看后者，听完的长短看前者。RTF 从 1.08 升到 1.35，仍在 ≤2 预算内。
- 拆段还会给第二段带入**重复音节**（叠字）：`每次六点七毫克。服用后请漱口` 8 次里 3 次（`请请漱口`）；
  数字形态 8 次复测 0 次，但现场听到的那一条原件确实是 `请请`。不加边界的同一句两档都是 0 次。
  判叠字必须用**带调**拼音：去调比会把 `轻/请` 这种 ASR 同音选字当成模型多念（我错过一次，见
  `docs/device-runtime-check.md` 的更正）。
  但 `21床。正在呼叫` 仍然 8/8 干净，不普遍。
- 单位表按最长优先，且**长单位被否后不许退回短单位**——退回去会切出 `30分。钟后` 这种破词（真踩过）。

## 实现侧要守的判定（改规则前先读）

单字数量不加（`三床`、`十分`）；数量+方位/范围词不加（`30分钟后`、`37.5度以下`）；
原文已带任何断句标点整句放行（与长句切分互斥，叠起来会超过两刀）；
数字块内部绝不切；边界总数 ≤2。
